# 蓝牙遥控故障排查记录

> 问题：iOS App 通过 HM-10 BLE 模块发送控制指令，小车无反应。

---

## 1. 回顾：三个已知固件 Bug（已修复）

在开始硬件排查之前，先确认了以下三个 Bug 已经在 `master` 分支上修好：

| Bug | 位置 | 修复内容 |
|-----|------|---------|
| `USART_RX_STA` 缺 `volatile` | `SYSTEM/usart/usart.c:44`, `usart.h:21` | 加 `volatile`，防止编译器缓存导致主循环看不到 ISR 更新 |
| 断连超时用循环计数器 | `USER/main.c:13,38,86` | 改用 SysTick 毫秒计时 `bt_tick`，500ms 阈值 |
| `delay_ms()` 后 SysTick 时钟源丢失 | `USER/main.c:61,76` | 补 `SysTick_CLKSourceConfig(HCLK_Div8)` |

**提交记录**：`97cdd14`、`0db173f`、`e87070f`

---

## 2. 加调试 printf 输出

在 `bluetooth_cmd_parse()` 中加了 `printf` 调试输出，通过 USART1 TX (PA9) 发出，可用 CH340 USB-TTL 模块在电脑上监控。

**修改文件**：`USER/main.c`

**输出内容**：
- 上电后：`=== STM32 Car Boot ===`
- 收到指令：`[RX len=N:XXX]` + 解析结果（`CMD: FWD` / `CMD: STOP` / `CMD: BADLEN` 等）

**注意**：ARMCC V5.06 是 C90 编译器，`for (u8 i = ...)` 语法不合法，需将 `i` 提到函数开头声明。

## 3. 硬件接线

### 关键器件

| 器件 | 用途 |
|------|------|
| CH340 USB-TTL 模块 | 电脑 USB → UART 串口，用于收发数据 |
| HM-10 BLE 模块 | 蓝牙 4.0 透传，iOS App ↔ STM32 的桥梁 |
| P16 接口（扩展板） | 8 针双排座，引出 VCC / RXD / TXD / GND 供 HM-10 使用 |

### P16 引脚（经验证）

| 信号 | 方向 | 说明 |
|------|------|------|
| VCC | 输出 3.3V | 给 HM-10 供电 |
| RXD | 输入 STM32 (PA10) | HM-10 TXD 接这里 |
| TXD | 输出 STM32 (PA9) | HM-10 RXD 接这里 |
| GND | 公共地 | 必须共地 |

---

## 4. 排查过程

### 步骤 1：CH340 自环测试

**操作**：CH340 TXD 和 RXD 用杜邦线短接，PuTTY/SSCOM 开串口 (9600 8N1)，打字看是否有回显。

**目的**：确认 CH340 模块和串口工具正常工作。

**结果**：回显成功。

---

### 步骤 2：CH340 直连 STM32（绕过蓝牙）

**接线**：

| CH340 | P16 |
|-------|-----|
| GND | GND |
| RXD | TXD (PA9) |
| TXD | RXD (PA10) |
| VCC | **不接**（STM32 已有电池供电，两路电源不能并） |

**操作**：SSCOM 开串口，发送 hex `4F 4E 41 0D 0A`（即 `ONA\r\n`）。

**目的**：验证 STM32 固件的指令接收→解析→电机驱动全链路。

**结果**：
- 上电后 SSCOM 显示 `=== STM32 Car Boot ===`
- 发送 `ONA\r\n` 后显示 `[RX len=3:ONA]` + `CMD: FWD`
- **车轮转动，约 0.5 秒后自动停止**

**结论**：固件的 UART 接收、指令解析、电机驱动全链路正常。0.5 秒停止是断连超时保护机制（`BT_TIMEOUT_MS = 500`），单发一次指令只跑 0.5 秒，需周期性重发。

**关键信息**：CH340 TXD 插入的 P16 那个孔是 STM32 RX (PA10)。这个孔的位置被记录下来，后续 HM-10 TXD 必须插同一个孔。

---

### 步骤 3：HM-10 直连 CH340（验证蓝牙链路）

**接线**（HM-10 从 P16 拔下，只接 CH340）：

| HM-10 | CH340 |
|-------|-------|
| VCC | 3V3（这次允许，因 HM-10 不再连扩展板） |
| GND | GND |
| TXD | RXD |
| RXD | TXD |

**操作**：SSCOM 监听，iOS App 配对 HM-10 后按前进按钮。

**目的**：验证 iOS App → HM-10 BLE → HM-10 UART 这一段链路是否正常。

**结果**：
- iOS App 点击前进：SSCOM 显示 `ONA`
- 松手后：SSCOM 显示 `ONF`
- **长按前进：多次重复 `ONA`**

**结论**：iOS App 蓝牙通信正常，HM-10 BLE 透传正常，协议字节正确。

---

### 步骤 4：HM-10 接回 P16 + CH340 监听 STM32 TX

**接线**：

| HM-10 | P16 |
|-------|-----|
| VCC | VCC |
| GND | GND |
| TXD | RXD (PA10)（与步骤 2 同一个孔） |
| RXD | TXD (PA9) |

CH340 RXD 接到 P16 TXD (PA9)，GND 共地，**只监听不发送**。

**操作**：SSCOM 开串口，iOS App 配对后按前进。

**预期**：
- 上电出现 `=== STM32 Car Boot ===`
- iOS 发指令后出现 `[RX len=3:ONA]` + `CMD: FWD`

**实际结果**：
- 只看到 `=== STM32 Car Boot ===`
- iOS 发指令后**无任何新输出**

**含义**：STM32 在跑（boot 消息出现），但 USART 中断没触发——HM-10 TXD 的信号没到达 STM32 RX。

---

### 步骤 5：排除杜邦线本身断路

**操作**：万用表蜂鸣档测试 HM-10 TXD 那根杜邦线两端。

**结果**：蜂鸣，线芯无断路。

**含义**：线本身是好的。故障可能是线两端接头与 P16 公针/ HM-10 引脚的**接触不良**。

---

### 步骤 6：回归验证（HM-10 直连 CH340 再次确认）

**操作**：HM-10 TXD → CH340 RXD，HM-10 RXD → CH340 TXD，HM-10 由小车供电。iOS App 操作。

**结果**：所有指令（前进/后退/左转/右转/停止/调速）在 SSCOM 均有正确回显。

**含义**：HM-10 模块工作完全正常，BLE 链路和 UART 输出都没问题。

---

## 5. 当前结论

| 已验证 | 状态 |
|--------|------|
| 固件：指令解析 + 电机驱动 | 正常（CH340 直连时车会动） |
| iOS App：BLE 连接和数据发送 | 正常 |
| HM-10：BLE 接收 + UART 透传 | 正常（直连 CH340 可看到数据） |
| HM-10 TXD → P16 连接 | **存在接触不良** |

### 故障定位

虽然 HM-10 TXD 杜邦线蜂鸣测试通过（线芯完好），但实际工作状态下数据无法从 HM-10 传到 STM32。CH340 TXD 插同一个 P16 孔时能工作，说明：

- P16 的 RX 孔本身是好的
- HM-10 TXD 这根杜邦线的**母头簧片**与 P16 公针之间可能没有真正咬合
- 蜂鸣测试时万用表静态电流能通过，但实际 UART 信号边缘陡峭，接触电阻稍大就会导致逻辑电平无法识别

---

## 6. 待尝试的解决方案

### 方案 A：换一根新的杜邦线

用一根全新、从未用过的母-母杜邦线替代 HM-10 TXD → P16 这根线。两端确保插到底。

### 方案 B：在 HM-10 TXD 引脚上叠两个母头（并联监听）

不剪线。利用 HM-10 模块上 TXD 公针较长，在同一根公针上叠两个母头：
- 母头 1：HM-10 TXD → P16 RX（数据进 STM32）
- 母头 2：HM-10 TXD → CH340 RXD（SSCOM 同时监听）

这样可以实时看到信号到底有没有到达这个物理节点。

### 方案 C：在 P16 一侧叠两个母头

如果 P16 公针够长，把 CH340 RXD 的母头也叠在 P16 RX 同一个公针上（跟方案 B 方向相反，原理相同）。

## 7. 附带确认的知识点

| 知识点 | 说明 |
|--------|------|
| VCC 不接的原因 | CH340 和 STM32 各有独立电源，USB 5V 和板载 3.3V 不能并在一起，否则可能烧芯片 |
| 串口通信只需三根线 | GND + TXD + RXD，GND 是公共参考地 |
| 小车 0.5 秒自动停 | 固件设计了 500ms 断连超时，无新指令即停车。iOS App 按住按钮时每隔约 100~200ms 重发一次 `ONA`，松手发 `ONF` |
| ARMCC V5.06 仅支持 C90 | `for` 循环内不能声明变量（如 `for (u8 i = 0; ...)` 会报错），需提到函数开头 |
| `delay_ms()` 的副作用 | 会覆盖 SysTick->CTRL 并关闭 TICKINT 中断，调用后必须重新配置 SysTick（含 `CLKSourceConfig`） |
